# LuaHUD v0.3.0

## Features

- Added `opacity` to sections, canvases and individual draw calls. Values range from `0` (invisible) to `1` (fully opaque) and multiply with color alpha and the containing section or canvas opacity.
- Profiles now reload independently when their scripts or active states change, preserving other profiles' state and event listeners.
- Added mutable `Color` values for creating, editing and reusing colors in your HUDs.
- Added `lh.getOption(name)` to read Minecraft client settings using their `options.txt` names, with completions and typed return values for the current Minecraft version.

## API

### Added

- `lh.color.rgb(r, g, b, a?)`, `lh.color.from(value)` and `lh.color.fromRgb(value)`.
- `Color` fields: mutable `r`, `g`, `b` and `a` channels, plus `asInt` (ARGB) and `asString` (`#AARRGGBB`) conversions. Drawing color options accept `Color` tables alongside integers and hex strings.
- `lh.display.isHudHidden` to check whether Minecraft's HUD is hidden.
- `ItemStack.maxCount`.
- The `reload` event now receives a list of the profiles loaded by that reload. Each `Profile` exposes `name`, `active`, `hidden` and `keybind`.
- Addons can define mutable table models with `ModelBuilder.mutableTable()` and access the built-in `Profile` model.

### Changed

- `lh.biome.waterColor`, `skyColor`, `foliageColor` and `grassColor` now return `Color` values instead of integers. Use `.asInt` when a packed integer is needed.
- `lh.perf.maxFps` now returns `260` instead of `-1` when the frame rate limit is unlimited, matching Minecraft's stored value.
- CPU and GPU usage readings no longer use LuaHUD's one-second cache.

## Improvements

- Improved generated Lua stubs for overloaded functions and functions inside namespaces.
- Simplified copied error messages and added a documentation link to Mod Menu.
